# EMA ePI labels

**Source: European Medicines Agency.** The files in `sources/` are byte copies of summaries of
product characteristics that the EMA publishes as electronic product information (ePI) through
its public API, `https://epi.ema.europa.eu/consuming/api/fhir`. They are reproduced with
acknowledgement of the source, as the EMA's legal notice permits.

**Not medicines information.** The EMA publishes these ePIs for pilot purposes only; they may
not be up to date. The current product information for each medicine is on its EPAR page,
linked from `sources.lock.json`.

They are here for two purposes, under the scoped exception in `AGENTS.md`: to test the QRD
conformance check (`docs/design/qrd-conformance-check.md`) on real, authority-published text,
and to test the authority importer (`docs/design/authority-import-contract.md`), which reads a
document only with the EMA List that indexes it. `sources.lock.json` pins each document and its
List (`lists/`) by SHA-256 with their URLs, the date each was retrieved, and the EMA ePI
identifier, procedure number, marketing authorisation holder and composition date that those
bytes carry. They are also read by the importer's golden vectors (`src/authority/vectors.ts`)
and the renderer checks (`scripts/render/`).

The lock is written only by `zone-a/scripts/pin_label.py` (in `zone-a/`,
`uv run --frozen python scripts/pin_label.py FILE` re-pins a label; its docstring shows how to
add one). It fetches as the import gate does, writes the bytes, and records each file's own
retrieval date and the metadata read from the bytes, never typed in.
`zone-a/tests/test_qrd_check.py` reads the metadata back from the pinned bytes and fails on an
entry that disagrees, and `checks/` must hold exactly one result per pinned label. The pinned
files are marked `-text` in `.gitattributes`, so no line-ending conversion touches the bytes the
lock hashes.

`checks/` holds the QRD check's results, generated by `zone-a/scripts/check_labels.py` and
compared with a fresh run in CI. `zone-a/scripts/check_label_sources.py` compares every pinned
file with the live API, fetching as the import gate does, on demand and weekly
(`.github/workflows/ema-drift.yml`, which opens an issue on a difference and never gates a pull
request).
