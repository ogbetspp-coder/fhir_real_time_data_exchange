# Recorded change: `query-tools` 2.0.1 and the `src/fidelity/index.ts` re-export, 2026-09-22

_Moved verbatim from `docs/validation/README.md`, whose "Change control for shared, evidenced
libraries" section holds the procedure (steps 0–8) this record follows. The UR- rows and
section names it cites ("above", "Release criteria") are in that file._

**What changed.** `QUERY_TOOLS_VERSION` moved from `2.0.0` to `2.0.1`, a patch under ADR 0002:
no field, enum member or bound changed; the published descriptions of `QuoteVerification`,
`SectionContent` and `ProvenanceDetail` did, and so did three tool descriptions the service serves
through `tools/list` (`verify_quote`, `get_section`, `get_provenance`, in `src/query/app.ts`).
What they describe changed with them. `verify_quote`'s `match` now requires both edges of the
quote to hold under the quote-edge rule (UR-22), where under 2.0.0 it meant any contiguous slice
of the normalised text; an approval — `get_provenance`'s answer, `get_section`'s
`provenanceResourceId` — is given for a document's current version only, and is the most recently
written approval rather than the most recently dated (UR-47). Separately, `src/fidelity/index.ts`
re-exports `isWordCharacter`, which `src/fidelity/normalize.ts` already exported and
`src/fidelity/verify.ts` already used; nothing in the function moved.

**Why.** The repository review of 2026-09-22 found `verify_quote` confirming quotes cut inside a
word and an earlier version answered with a later version's approval. The independent review of
the first fix, the same day, found that the fix still confirmed quotes cut at punctuation — the
gate's span-edge rule, which it had reused, was built for a check that is followed by full
equality, and a quote is followed by nothing — that the approval was chosen by approval date
rather than by write order, and that recording the change as comment-only was wrong: descriptions
a client reads had changed, and `match` means something stricter. A first draft of this record
said nothing published had changed and left the version at `2.0.0`; that was incorrect and is
replaced by this one.

**Impact assessment (step 0).** Importers: `src/contracts/query-tools.ts` is imported by the
query service and the contract generator; the Python agent reads the generated schema through its
vendored copy. `src/fidelity/index.ts` is imported by `src/query/tools.ts`,
`src/contracts/canonical-submission.ts`, `src/fixtures/synthetic-submission.ts`,
`src/fhir/provenance.ts` (a type) and two scripts; the added export changes none of them, and Zone
A's Python port is untouched because no normalisation or verification rule changed —
`NORMALIZATION_VERSION` stays `fidelity-norm/1.1.1` and the fidelity vectors are byte-identical.
Previously produced evidence: every `verify_quote` `match` recorded under `query-tools` 2.0.0 —
an `ok` audit outcome with `resultCount: 1`, and the agent post-check's verified chunks built on
it — was decided by the looser rule. Those records remain as recorded and are not re-evaluated;
from this change on they are distinguishable by the contract version the service and the agent
carry. The audit record's shape is unchanged. No approved hash moves, so step 7 does not apply.

**Steps 1–6.** 1: `QUERY_TOOLS_VERSION` is `2.0.1`. 2: `contracts/generated/query-tools.schema.json`
and `contracts/generated/index.json` regenerated (`$id` `…/query-tools/2.0.1/schema.json`);
`agent/scripts/sync_contract.py` rewrote the vendored copy, which is byte-identical to the
published one (`--check` passes); `agent/tests/test_contract.py` pins `/2.0.1/`. 3: no fidelity
vector changed. 4: the adversarial cases are the two acceptance tests named in UR-22 and UR-47 and
the reader test named in UR-47; each fails against the code before this change. 5: ADR 0002 and
ADR 0003 are unchanged — the gate's rule is not touched; the quote-edge rule is stated in
`docs/design/epi-mcp-query-service.md`. 6: UR-18, UR-22, UR-42 and UR-47 above.

**Blast radius.** A client that sent quotes cut inside a word or at joined punctuation now
receives `no-match`. The agent's post-check splits blocks only at U+0020, so its chunks end on
spaces; a chunk boundary that falls inside a space-grouped number or just after a spaced
comparator, and a single token longer than the 2,000-unit window, are now `no-match` — fail
closed. A client that asked `get_provenance` for an earlier version now receives `unavailable`
where it previously received another version's approval, and a document whose current version was
approved before an earlier one now answers with the approval written with it. The agent's test
double (`agent/tests/fake_query_service.py`) still matches by plain substring and is looser than
the service; it is not changed here. The agent's own test suite was not run in this change (its
toolchain is not installed on the machine that made it); the contract sync check was.

**Approval (step 8).** Not obtained: author and releaser are the same identity. Branch protection
on `main` does exist and requires status checks, but it requires no reviewer, so nothing forces a
second pair of eyes (see "Release criteria").
